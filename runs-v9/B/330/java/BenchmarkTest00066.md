## Verdict

exploitable (confidence: high)

CWE-330 (Use of Insufficiently Random Values), `BenchmarkTest00066.java:74`.

## Source

`java.lang.Math.random()` at line 74. Its return value is converted straight to a digit string with no other entropy mixed in.

## Fix

No third-party library needed; the JDK's own `java.security.SecureRandom` replaces `Math.random()` directly.

**Vulnerable code (lines 66-75):**

```java
String bar;

// Simple if statement that assigns constant to bar on true condition
int num = 86;
if ((7 * 42) - num > 200) bar = "This_should_always_happen";
else bar = param;

// SAST FINDING: CWE-330 (Use of Insufficiently Random Values) - a security-relevant value is drawn from a non-cryptographic PRNG. Sink is the next statement.
double value = java.lang.Math.random();
String rememberMeKey = Double.toString(value).substring(2); // Trim off the 0. at the front.
```

**Fixed code:**

Add a shared generator as a class field, alongside the existing `serialVersionUID`:

```java
private static final long serialVersionUID = 1L;
private static final java.security.SecureRandom SECURE_RANDOM = new java.security.SecureRandom();
```

Replace the token derivation:

```java
String bar;

// Simple if statement that assigns constant to bar on true condition
int num = 86;
if ((7 * 42) - num > 200) bar = "This_should_always_happen";
else bar = param;

// Generate the remember-me token from a cryptographic RNG, not Math.random().
byte[] tokenBytes = new byte[16]; // 128 bits, per OWASP ASVS floor for a non-guessable token
SECURE_RANDOM.nextBytes(tokenBytes);
String rememberMeKey =
        java.util.Base64.getUrlEncoder().withoutPadding().encodeToString(tokenBytes);
```

## Explanation

`rememberMeKey` is a persistent-login secret: it is written into the `rememberMe<N>` cookie and into the session, and a later request is authenticated by comparing the cookie's value against the stored one (lines 84-119). `Math.random()` is backed by a 48-bit linear congruential generator; observing a handful of outputs (or even one, combined with the roughly-known call time) lets an attacker reconstruct the internal state and predict or reproduce future values, so the "remember me" token is guessable rather than secret. The fix swaps the source for `SecureRandom`, drawing 16 raw bytes (128 bits of entropy, meeting the ASVS floor for a non-guessable value) and encoding them with `Base64.getUrlEncoder().withoutPadding()` rather than converting a float to a decimal string - `Double.toString(...).substring(2)` on a `SecureRandom`-produced double would still narrow and bias the output, so the fix draws bytes directly instead of changing the input to the same lossy conversion. `new SecureRandom()` (not `getInstanceStrong()`) is used to avoid the documented blocking-entropy-source hang on Linux/macOS in a request path, and the instance is a shared `static final` field per the JDK's own thread-safety guarantee for `SecureRandom`, avoiding a fresh provider lookup and self-seed on every request.

## Behaviour changes

- **Token format**: the cookie/session value changes from a decimal-digit string (e.g. `"53728..."`, length varying with the double's representation) to a URL-safe Base64 string of fixed length (22 characters for 16 bytes, alphabet `A-Za-z0-9-_`). Both call sites that consume this value use it only for opaque string equality (`cookie.getValue().equals(...)` at line 92, and setting the cookie/session attribute) and never parse it as a number, so this is behaviourally inert - not a functional change, only worth flagging because the visible cookie value looks different. Base64url's character set contains no characters `Cookie` rejects, so no cookie-encoding issue is introduced.
- **Token length**: fixed at 22 characters versus the original's variable length (typically 15-17 digits, since `Double.toString` trims trailing zeros). No downstream code depends on a specific length.
- **New field**: adds a `private static final SecureRandom SECURE_RANDOM` field to the class. This is additive and does not change any existing method's signature or the class's public contract.
- Previously issued `rememberMe<N>` cookies (or session attributes) generated by the old `Math.random()` path are not invalidated by this change alone - they remain valid, guessable secrets until they expire naturally (3-minute `Cookie` max-age set in `doGet`, and for the lifetime of the session for the session attribute). No code in this file performs bulk rotation; deploying the fix stops new guessable tokens from being issued but does not revoke ones already handed out.
