## Verdict

Confirmed: CWE-22 path traversal at line 23. The `file` parameter is concatenated with `_reportsRoot` via `Path.Combine()` without validating that it is a relative path. `Path.Combine()` discards the first argument when the second is an absolute path, allowing an attacker to read arbitrary files on the filesystem.

## Source

The vulnerability lies in the data flow from the user-controlled `file` query parameter (line 15) to `Path.Combine()` (line 20) and then to `File.ReadAllText()` (line 23). The code assumes the combined path will always be within `_reportsRoot`, but `Path.Combine()` does not enforce this constraint.

Example attack: `GET /api/reports/export?file=C:\Windows\System32\config\SAM` bypasses the root directory and reads the SAM file directly.

## Fix

### File: PathCombineAbsoluteOverride.cs

```csharp
using Microsoft.AspNetCore.Mvc;

namespace EvalCases.Controllers;

[ApiController]
[Route("api/[controller]")]
public class ReportsController : ControllerBase
{
    // Reports generated by the application are normally written here and
    // nowhere else; the intent is that this endpoint can only ever serve
    // files from this directory.
    private readonly string _reportsRoot = @"C:\App\Data\Reports";

    [HttpGet("export")]
    public IActionResult ExportReport([FromQuery] string file)
    {
        // Validate that file is a relative path and does not attempt traversal
        if (string.IsNullOrWhiteSpace(file) || Path.IsPathRooted(file) || file.Contains(".."))
        {
            return BadRequest("Invalid file path");
        }

        var reportPath = Path.Combine(_reportsRoot, file);

        // Resolve the full path and verify it remains within the reports root
        var fullReportPath = Path.GetFullPath(reportPath);
        var fullReportsRoot = Path.GetFullPath(_reportsRoot);

        if (!fullReportPath.StartsWith(fullReportsRoot + Path.DirectorySeparatorChar, StringComparison.OrdinalIgnoreCase))
        {
            return BadRequest("Invalid file path");
        }

        // SAST FINDING: CWE-22 (Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')) reported here. Sink is the next statement.
        var reportText = System.IO.File.ReadAllText(fullReportPath);

        return Content(reportText, "text/plain");
    }
}
```

## Explanation

The fix uses three layers of validation:

1. **`Path.IsPathRooted(file)`** rejects absolute paths like `C:\Windows\System32\config\SAM` or `/etc/passwd`, preventing `Path.Combine()` from discarding the root directory.

2. **`file.Contains("..")`** rejects directory traversal sequences that attempt to escape the reports directory.

3. **`Path.GetFullPath()` + `StartsWith()` check** verifies that the resolved file path is actually within the intended reports directory, catching any remaining edge cases. The check uses `StringComparison.OrdinalIgnoreCase` to match Windows path semantics.

Together, these checks ensure that `file` can only reference files directly within or beneath `_reportsRoot`, closing the path traversal vulnerability.
