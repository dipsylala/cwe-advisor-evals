## Verdict

CONFIRMED. The code directly uses the client-supplied filename to construct a file path without validation, creating an unrestricted file upload vulnerability. An attacker can:
- Upload files with dangerous extensions that could be executed or misused
- Use path traversal sequences (e.g., `../`) to write outside the intended upload directory
- Bypass access controls on the storage location

## Source

Line 28 constructs the destination path using `file.FileName` without any validation:

```csharp
var destination = Path.Combine(uploadRoot, file.FileName);
```

The file extension and path components are not validated against a whitelist, and the original filename is trusted from an untrusted HTTP request.

## Fix

### File: UploadOutsideWebroot.cs

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Threading.Tasks;
using Microsoft.AspNetCore.Hosting;
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Mvc;

namespace EvalCases;

[ApiController]
public class UploadOutsideWebrootController : ControllerBase
{
    private readonly IWebHostEnvironment _env;

    // Allowlist of safe file extensions
    private static readonly HashSet<string> AllowedExtensions = new(StringComparer.OrdinalIgnoreCase)
    {
        ".pdf", ".txt", ".docx", ".xlsx", ".jpg", ".png", ".gif"
    };

    public UploadOutsideWebrootController(IWebHostEnvironment env) => _env = env;

    [HttpPost("/upload")]
    public async Task<IActionResult> Upload(IFormFile file)
    {
        if (file is null || file.Length == 0)
        {
            return BadRequest();
        }

        // Validate file extension against allowlist
        var extension = Path.GetExtension(file.FileName);
        if (string.IsNullOrEmpty(extension) || !AllowedExtensions.Contains(extension))
        {
            return BadRequest("File type not allowed");
        }

        var uploadRoot = Path.Combine(_env.ContentRootPath, "storage", "uploads");
        Directory.CreateDirectory(uploadRoot);

        // Generate a safe filename using GUID to prevent path traversal and filename collision
        var safeFileName = $"{Guid.NewGuid()}{extension}";
        var destination = Path.Combine(uploadRoot, safeFileName);

        await using var stream = System.IO.File.Create(destination);
        await file.CopyToAsync(stream);

        return Ok(new { stored = safeFileName, bytes = file.Length });
    }
}
```

## Explanation

The remediation implements two core controls:

1. **Extension allowlist validation** (lines 12-15, 33-37): Only file types explicitly declared safe are accepted. This prevents uploading dangerous executables (`.exe`, `.aspx`, `.php`, etc.) that could be executed by the server or browser.

2. **Safe filename generation** (lines 45-46): Instead of using the untrusted `file.FileName`, a GUID-based filename is generated with the original extension appended. This prevents:
   - Path traversal attacks using `../` sequences
   - Overwriting existing files
   - Directory-level attacks exploiting reserved or special filenames

The validation occurs before any file I/O, so invalid uploads fail immediately. The response returns the safe filename generated by the server rather than echoing the user's input, preventing information disclosure.

The allowlist is configured as a case-insensitive set to handle various extension casings. Update the `AllowedExtensions` set according to your application's actual requirements.
