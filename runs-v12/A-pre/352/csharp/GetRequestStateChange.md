## Verdict
CONFIRMED: CWE-352 (Cross-Site Request Forgery)

The `DeleteAccount` action method performs a state-changing operation (account deletion) in response to an HTTP GET request. This violates the fundamental CSRF defence principle that only POST/PUT/DELETE requests should mutate server state, because GET requests automatically include session cookies across origins and can be triggered by an attacker's page without user awareness or explicit form submission.

## Source
File: `evals/cases/352/csharp/GetRequestStateChange/AccountController.cs`
Line: 32

The vulnerable method:
```csharp
[HttpGet("delete")]
public async Task<IActionResult> DeleteAccount(bool confirmed)
{
    if (!confirmed)
    {
        return RedirectToAction(nameof(ConfirmDelete));
    }

    var userId = _userContext.CurrentUserId;
    await _accountService.DeleteAccountAsync(userId);

    return RedirectToAction("SignedOut", "Home");
}
```

## Fix
1. Change the route attribute from `[HttpGet("delete")]` to `[HttpPost("delete")]`
2. Add the `[ValidateAntiForgeryToken]` attribute to the method to require an anti-forgery token with the request
3. Update the confirmation page's form to use POST with a form submission rather than a GET link

Corrected method signature:
```csharp
[HttpPost("delete")]
[ValidateAntiForgeryToken]
public async Task<IActionResult> DeleteAccount(bool confirmed)
```

The confirmation page should use:
```html
<form method="post" action="@Url.Action("DeleteAccount", "Account")">
    @Html.AntiForgeryToken()
    <input type="hidden" name="confirmed" value="true" />
    <button type="submit">Yes, delete my account</button>
</form>
```

## Explanation
A POST request combined with `[ValidateAntiForgeryToken]` provides two layers of CSRF protection:

1. **Request method enforcement**: POST requests are not automatically sent by browsers on navigation or resource loads (unlike GET). An attacker cannot trigger the action with a simple `<img>` tag or link.

2. **Anti-forgery token validation**: The `[ValidateAntiForgeryToken]` attribute requires a token (generated by `@Html.AntiForgeryToken()`) to be present and valid in the request. This token is bound to the user's session and cannot be read cross-site due to the same-origin policy. An attacker's page cannot obtain or include a valid token, so even if they craft a POST request, it will be rejected.

By restricting account deletion to POST with CSRF protection, the application ensures that state-changing operations cannot be performed without explicit user action and valid request verification.
