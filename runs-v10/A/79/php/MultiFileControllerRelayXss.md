## Verdict
Confirmed CWE-79 vulnerability. User-controlled input flows from `$_POST['comment']` and `$_POST['customer_name']` through TicketController → TicketService → NotificationDispatcher and is output to HTML without escaping at ConfirmationPageRenderer.php line 11.

## Source
- **TicketController.php line 12**: `$comment = $_POST['comment'] ?? '';`
- **TicketController.php line 11**: `$customerName = trim($_POST['customer_name'] ?? 'Guest');`

Both values are user-controlled HTTP request parameters without sanitization.

## Fix
In **ConfirmationPageRenderer.php line 11**, change:

```php
echo '<p>' . $message . '</p>';
```

to:

```php
echo '<p>' . htmlspecialchars($message, ENT_QUOTES, 'UTF-8') . '</p>';
```

Also escape the `$ticketId` on line 9 as a defence-in-depth measure, though it is internally generated by `uniqid()`:

```php
echo '<div class="confirmation" data-ticket-id="' . htmlspecialchars($ticketId, ENT_QUOTES, 'UTF-8') . '">';
```

## Explanation
The `$message` variable is built by concatenating user-supplied input without any encoding. When output to HTML context via `echo`, it allows an attacker to inject arbitrary HTML and JavaScript. The fix uses `htmlspecialchars()` with `ENT_QUOTES` to convert special characters (`<`, `>`, `"`, `'`, `&`) to HTML entity references, preventing script injection while preserving the message content for legitimate display. The `UTF-8` encoding parameter ensures correct handling of multibyte characters.
