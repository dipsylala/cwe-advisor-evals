## Verdict

exploitable

## Source

`file.originalname` (attacker-controlled multipart upload metadata)

## Fix

**Vulnerable code (lines 7-28):**

```javascript
const BLOCKED_EXTENSIONS = ['.exe', '.php', '.sh', '.bat'];

const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, path.join(__dirname, 'uploads')),
  filename: (req, file, cb) => cb(null, file.originalname),
});

function rejectKnownDangerousExtensions(req, file, cb) {
  const ext = path.extname(file.originalname).toLowerCase();
  if (BLOCKED_EXTENSIONS.includes(ext)) {
    return cb(new Error(`File type ${ext} is not allowed`));
  }
  return cb(null, true);
}

const upload = multer({
  storage,
  fileFilter: rejectKnownDangerousExtensions,
});
```

**Fixed code:**

```javascript
const express = require('express');
const multer = require('multer');
const path = require('path');
const fs = require('fs');
const crypto = require('crypto');

const router = express.Router();

// Allowlist of permitted MIME types
const ALLOWED_MIME_TYPES = new Set(['image/jpeg', 'image/png', 'application/pdf', 'text/plain']);

const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, path.join(__dirname, 'uploads')),
  filename: (req, file, cb) => {
    // Generate a random filename; extension added after content validation
    cb(null, crypto.randomUUID());
  },
});

const upload = multer({
  storage,
  limits: { fileSize: 10 * 1024 * 1024 }, // 10MB limit
});

router.post('/attachments', upload.single('attachment'), async (req, res) => {
  if (!req.file) {
    return res.status(400).json({ error: 'No file uploaded' });
  }

  try {
    const { fileTypeFromBuffer } = await import('file-type');
    
    // Read the uploaded file and check magic bytes
    const fileBuffer = fs.readFileSync(req.file.path);
    const detected = await fileTypeFromBuffer(fileBuffer);
    
    // Validate against allowlist of MIME types
    if (!detected || !ALLOWED_MIME_TYPES.has(detected.mime)) {
      fs.unlinkSync(req.file.path);
      return res.status(400).json({ error: 'File type not allowed' });
    }
    
    // Rename file with validated extension from magic bytes, not client input
    const finalFilename = `${crypto.randomUUID()}.${detected.ext}`;
    const finalPath = path.join(__dirname, 'uploads', finalFilename);
    fs.renameSync(req.file.path, finalPath);
    
    return res.status(201).json({
      message: 'Attachment uploaded',
      path: finalFilename,
    });
  } catch (err) {
    // Clean up file on error
    if (req.file && req.file.path && fs.existsSync(req.file.path)) {
      fs.unlinkSync(req.file.path);
    }
    return res.status(500).json({ error: 'File processing failed' });
  }
});

module.exports = router;
```

## Explanation

The original code relied on a denylist of dangerous extensions, which is fundamentally unsafe because it assumes anything not explicitly blocked is safe. Attackers can evade this by using numerous other dangerous extensions (.com, .scr, .aspx, .jsp, .py, etc.) or by spoofing extensions entirely. The fix replaces the extension denylist with magic-byte validation against an allowlist of permitted MIME types. The `file-type` library inspects the actual file content (magic bytes) rather than trusting the client-supplied filename or Content-Type header. Validation is moved from the `fileFilter` function (which runs before the file is written) to the route handler (after multer has buffered or written the file), making the content available for inspection. The stored filename is generated using `crypto.randomUUID()` with the extension derived from the detected type, eliminating reliance on the client-supplied `originalname`. File size is capped at 10 MB to reject oversized uploads early. If validation fails, the partially written file is deleted before responding. This ensures only files matching the allowlist's MIME types are retained, closing the unrestricted upload vulnerability.

## Behaviour changes

1. **File validation moved to route handler**: The unsafe `fileFilter` function is removed. Validation now occurs after multer has written the file, when the actual bytes are available for inspection via `fileTypeFromBuffer()`.

2. **Magic bytes validation added**: The fix checks actual file content rather than trusting the extension. The `file-type` library reads the magic bytes (file signature), which is much harder to spoof than an extension.

3. **Denylist replaced with allowlist**: The fixed code validates against an explicit allowlist of permitted MIME types (`ALLOWED_MIME_TYPES`), only rejecting known-dangerous types but also rejecting unknown or unexpected types.

4. **Filename generation**: Files are stored with names generated by `crypto.randomUUID()` and the extension is derived from the detected MIME type (`detected.ext`), not from `file.originalname`. This prevents attackers from controlling the extension or filename.

5. **File size limit added**: `limits: { fileSize: 10 * 1024 * 1024 }` rejects uploads larger than 10 MB before they are written to disk, defending against resource exhaustion.

6. **Dynamic ESM import of file-type**: The `file-type` package is v17+, which is ESM-only. The fix uses `await import('file-type')` inside the async route handler to load it, required for CommonJS environments.

7. **Error cleanup**: If validation fails or an error occurs, the route handler explicitly deletes the temporary file using `fs.unlinkSync()`.

8. **Response path change**: The response returns only the generated `finalFilename` instead of the full filesystem path, reducing information disclosure.

9. **Async route handler**: The route handler is now `async` to support the `await import('file-type')` call. This is a safe conversion because Express handles returned Promises.

10. **fs module added as dependency**: The fix requires `const fs = require('fs')` for reading, deleting, and renaming files.
